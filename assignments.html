Set up Visual Studio Code and Live Server

In this tutorial, you will install Visual Studio Code, add the Live Server extension, and use it to preview an HTML file in your browser.

Submission: None.

1. Download Visual Studio Code

Go to Visual Studio Code. Download the version for your computer (Mac or Windows) and install it. Open Visual Studio Code after installation.

2. Install Live Server

In Visual Studio Code, click the Extensions icon on the left side of the window. Search for Live Server. Find the extension named Live Server by Ritwick Dey and click Install.

3. Download the class file

Download the file provided below and save it somewhere easy to find, such as your Documents or Desktop.

File url: https://github.com/jjjiia/data_visualization_course/blob/main/maze_to_tree.html

4. Open the file in Visual Studio Code

5. Start Live Server

Right-click anywhere in the HTML code and select Open with Live Server. Your web browser should open automatically. You should now see the HTML file displayed as a webpage. The address will look something like:

6. Test it

Make a small change to the HTML file—for example, change some text. Save the file: Command + S on Mac, Ctrl + S on Windows. Return to your browser. The page should automatically update. If it does, Visual Studio Code and Live Server are working correctly.

You’re ready!

GitHub Pages Due September 17th, 2026

Assignment: Create and Publish Your First GitHub Pages Website

Time estimate: 1–2 hours

Goal: create a GitHub repository, put a simple website into it, and publish that website using GitHub Pages.

By the end, you will have:

  • A GitHub account
  • First GitHub repository
  • A local copy of that repository on your computer
  • An index.html webpage
  • Your first Git commit
  • Your first GitHub push
  • A publicly accessible website

Your final website will have a URL like:
https://YOUR-USERNAME.github.io/YOUR-REPOSITORY/

Part 1: Create a GitHub account

If you do not already have one, create a GitHub account at GitHub. Your GitHub username will become part of the URL for your website.

Part 2: Install Git

You will use Git from the Terminal to manage and publish your files. Open Terminal and type:

git --version

If Git is installed, you should see something similar to:

git version 2.x.x

If you are using a Mac, Git may already be installed. If you are using Windows, download Git from Git SCM.

Part 3: Configure Git

In Terminal, enter:

git config --global user.name "Your Name"

Then:

git config --global user.email "your-email@example.com"

Use the email associated with your GitHub account. You can check your settings with:

git config --global --list

Part 3: Create a Personal Access Token

When you use Git from the Terminal to communicate with GitHub over HTTPS, GitHub does not use your normal account password. For this assignment, you will create a fine-grained Personal Access Token (PAT). A token acts as a credential that allows Git to communicate with your GitHub account.

Security warning
Treat your token like a password. Never:

  • Put it in an HTML file
  • Put it in JavaScript
  • Upload it to GitHub
  • Email it to someone
  • Post it in Slack or Discord
  • Include it in a screenshot

Go to your GitHub settings and find:
Settings → Developer settings → Personal access tokens → Fine-grained tokens

Choose: Generate new token

Give the token a name such as: class-github

Set an expiration date, give the token permission to read and write repository contents. Then generate the token.

Important: GitHub will only show you the token when it is generated. Copy it temporarily to a secure place. You will use it when Git asks for your password. When Git asks Username: enter your GitHub username. When it asks Password: paste your Personal Access Token.

Part 4: Create your repository on GitHub

Go to GitHub. Click: New repository. Give your repository a simple name (YOUR-REPO-NAME below) that is descriptive of your project, it will appear in the second part of your URL: YOUR-USERNAME.github.io/YOUR-REPO-NAME. Set the repository to: Public. Then click: Create repository.

Part 6: Create local folder and add your name

Download the file provided below, rename it index.html and place it in your class project folder on your computer. This folder will be your repo for this assignment.

File url: https://github.com/jjjiia/data_visualization_course/blob/main/maze_to_tree.html

Edit this html file as much or little as you want to familiarize yourself with the class workflow. When you are satisfied with how it looks locally, go on to the next step.

Part 7: Connect to GitHub

7A. Open Terminal in your website folder

First, find the folder containing your website files. For example, if your website is in your Documents folder:

cd ~/Documents/my-first-website

You can check that you are in the correct folder with:

ls

You should see your website files. For example: index.html

7B. Turn the folder into a Git repository

Run:

git init

You should see something like: Initialized empty Git repository... You have now turned your existing website folder into a Git repository.

7C. Connect your folder to GitHub

Now you need to tell your local Git repository where its online GitHub repository is located. On GitHub, open the repository you created earlier and follow the steps listed there or the steps below. These steps will connect your local folder to the repo online and allow you to push whatever code you write to it. Back in Terminal, run:

git remote add origin https://github.com/YOUR-USERNAME/my-first-website.git

For example:

git remote add origin https://github.com/janedoe/my-first-website.git

7D. Add your files

Tell Git to track the files in your website:

git add .

Then check:

git status

You should see your website files listed as files ready to be committed.

7E. Make your first commit

Create your first commit:

git commit -m "Create first website"

A commit is a saved snapshot of your project.

7F. Connect your main branch

Your GitHub repository uses a branch called main. To make sure your local branch is also called main, run:

git branch -M main

7G. Push your website to GitHub

Now send your website files to GitHub:

git push -u origin main

The origin tells Git which remote repository to push to. The main tells Git which branch to push. The -u tells Git to remember this connection so that future pushes can simply use:

git push

If Git asks for your credentials, enter your GitHub username and use your Personal Access Token as the password.

7H. Check GitHub

Go back to your repository on GitHub and refresh the page. You should now see your website files in the repository. For example:

my-first-website
    ├──index.html
    ├──style.css
    └──images/

Your existing website is now stored on GitHub.

Part 8: Turn on GitHub Pages

Now we will turn the repository into a website. On your GitHub repository, click: Settings. Then: Pages. Under: Build and deployment. Choose: Source: Deploy from a branch. Then select: Branch: main. And: Folder: / (root). Click: Save. GitHub will now build your website from the files in your repository.

Part 9: Find your website and submit

Your website will be located at:
https://YOUR-USERNAME.github.io/YOUR-REPOSITORY/

Notice the difference:

  • The first is where your code and files live — GitHub repository: https://github.com/janedoe/my-first-website
  • The second is where your website lives — GitHub Pages website: https://janedoe.github.io/my-first-website/

It can take several minutes for the site to become available. Submit to Courseworks your published website only.

For your reference

Git — Software on your computer that tracks changes to your files.

GitHub — An online service where your Git repositories can be stored and shared.

Repository — A project folder managed by Git. Your repository contains your HTML, CSS, JavaScript, images, and other project files.

GitHub Pages — A service that publishes static files from a GitHub repository as a website.

Anscombe’s Quartet Due September 24th, 2026

D3 Tutorial: Anscombe’s Quartet

Due: September 24th, 2026
Assigned: September 18th, 2026

Time estimate: 1–2 hours

Submission: Upload to your GitHub account and submit URL to Courseworks.

In this tutorial, we will use D3.js to:

  • Load Anscombe’s Quartet CSV data.
  • Draw a scatter plot using one set of numbers.
  • Turn our drawing code into a reusable function.
  • Use that function to draw all four datasets.

1. Set up your files

Create a folder called:

anscombes-quartet

Inside the folder, create:

index.html
script.js

You can use Visual Studio Code + Live Server to work on the project.

2. Add D3 to your HTML

Open index.html and add:

<!DOCTYPE html>
<html>
<head>
  <meta charset="UTF-8">
  <title>Anscombe's Quartet</title>
</head>

<body>

  <div id="chart">the chart will go here</div>

  <script src="https://d3js.org/d3.v7.min.js"></script>
  <script src="script.js"></script>

</body>
</html>

The first script loads D3. The second loads the JavaScript that we will write.

3. Get the data

Anscombe’s Quartet contains four datasets. Each dataset has an x and y variable. Download anscombe.csv and put it in the same folder.

4. Load the data

Open script.js. Start by loading the CSV:

d3.csv("anscombe.csv").then(function(data) {

  console.log(data); //This prints out the data

});

Open your browser’s developer console. You should see the data printed there.

Important: CSV data is loaded as text. We need to convert x and y into numbers. Change your code to:

d3.csv("anscombe.csv").then(function(data) {

  data.forEach(function(d) {
    d.x = +d.x;
    d.y = +d.y;
  });

  console.log(data);

});

The + converts a value such as "10" into the number 10.

5. Make an SVG

Inside the then function, create an SVG:

d3.csv("anscombe.csv").then(function(data) {

  data.forEach(function(d) {
    d.x = +d.x;
    d.y = +d.y;
  });

  const width = 500;
  const height = 500;

  const svg = d3.select("#chart")
    .append("svg")
    .attr("width", width)
    .attr("height", height);

});

We now have a blank 500 × 500 SVG.

6. Create scales

We need to convert our data values into positions on the screen. Create an x scale:

const xScale = d3.scaleLinear()
  .domain([0, 20])
  .range([50, 450]);

And a y scale:

const yScale = d3.scaleLinear()
  .domain([0, 12])
  .range([450, 50]);

Notice that the y range goes from 450 to 50. This is because SVG’s y-coordinate starts at the top of the screen.

7. Draw the first dataset

Let’s start with Dataset I. Filter the data:

const dataset1 = data.filter(function(d) {
  return d.dataset === "I";
});

Now use D3 to create a circle for every observation:

svg.selectAll("circle")
  .data(dataset1)
  .join("circle")
  .attr("cx", function(d) {
    return xScale(d.x);
  })
  .attr("cy", function(d) {
    return yScale(d.y);
  })
  .attr("r", 5);

You should now see a scatter plot.

8. Add axes

Create the axes:

const xAxis = d3.axisBottom(xScale);
const yAxis = d3.axisLeft(yScale);

Add them to the SVG:

svg.append("g")
  .attr("transform", "translate(0, 450)")
  .call(xAxis);

svg.append("g")
  .attr("transform", "translate(50, 0)")
  .call(yAxis);

Now your scatter plot should have axes.

9. Put the drawing code into a function

Right now, our code only draws Dataset I. But the four datasets have exactly the same structure. Instead of writing the same code four times, we can create a function. Create:

function drawScatterplot(dataset) {

  // drawing code goes here

}

Move the circle-drawing code into the function:

function drawScatterplot(dataset) {

  svg.selectAll("circle")
    .data(dataset)
    .join("circle")
    .attr("cx", function(d) {
      return xScale(d.x);
    })
    .attr("cy", function(d) {
      return yScale(d.y);
    })
    .attr("r", 5);

}

Now we can call the function:

drawScatterplot(dataset1);

10. Draw the other datasets

Create the other three datasets:

const dataset2 = data.filter(function(d) {
  return d.dataset === "II";
});

const dataset3 = data.filter(function(d) {
  return d.dataset === "III";
});

const dataset4 = data.filter(function(d) {
  return d.dataset === "IV";
});

Now we could call our function for each dataset:

drawScatterplot(dataset1);
drawScatterplot(dataset2);
drawScatterplot(dataset3);
drawScatterplot(dataset4);

However, there is one problem: all four datasets are being drawn into the same SVG. Instead, let’s create a separate SVG for each dataset.

11. Make the function create the entire chart

Move the SVG creation into the function:

function drawScatterplot(dataset) {

  const width = 500;
  const height = 500;

  const svg = d3.select("#chart")
    .append("svg")
    .attr("width", width)
    .attr("height", height);

  const xScale = d3.scaleLinear()
    .domain([0, 20])
    .range([50, 450]);

  const yScale = d3.scaleLinear()
    .domain([0, 12])
    .range([450, 50]);

  svg.selectAll("circle")
    .data(dataset)
    .join("circle")
    .attr("cx", function(d) {
      return xScale(d.x);
    })
    .attr("cy", function(d) {
      return yScale(d.y);
    })
    .attr("r", 5);

  svg.append("g")
    .attr("transform", "translate(0, 450)")
    .call(d3.axisBottom(xScale));

  svg.append("g")
    .attr("transform", "translate(50, 0)")
    .call(d3.axisLeft(yScale));
}

Now the function takes a dataset and creates a complete scatter plot.

12. Call the function four times

At the bottom of your d3.csv() function, call:

drawScatterplot(dataset1);
drawScatterplot(dataset2);
drawScatterplot(dataset3);
drawScatterplot(dataset4);

You should now have four scatter plots. The important idea is that we wrote the drawing code once and reused it four times.

Extra credit

Make each chart a different color without redrawing, by passing a color variable into the function and using it for the circle fill.

Final project data* Due October 29th, 2026

Due: October 29th, 2026

Goal: Acquire, document, and validate the datasets you plan to use for your final project. You should be able to clearly explain where your data came from, what it contains, and what you learned about the data through basic statistical analysis.

Submission: Make a final project repo containing data document and share the URL to the document via Courseworks.

Deliverables:

Submit a document containing your data sources, data dimensions, licensing information, descriptive statistics, and data-validation findings, along with links to your datasets.

Steps

1. Documented data sources

For each dataset, provide:

  • Name of the dataset
  • Organization or person that produced it
  • URL or location where you obtained it
  • Date you accessed it
  • Brief description of what the dataset contains
  • Try to download it to ensure it is manageable

2. Describe the size and structure of your data

Include:

  • Number of rows
  • Number of columns
  • What each row represents
  • What each important column represents
  • Data types of important variables
  • Coverage: time period, geography
  • When it was last updated, and when it will be updated next

3. Determine how you are allowed to use the data

Document:

  • The data license or terms of use
  • Whether the data is public domain, open data, copyrighted, etc.
  • Any attribution requirements
  • Any restrictions on modification, redistribution, or commercial use
  • A link to the original license or terms of use

4. Use descriptive statistics to explore and validate your data

Choose several variables that will be important to your final project and answer questions such as:

For numerical variables:

  • What is the minimum value?
  • What is the maximum value?
  • What is the mean?
  • What is the median?
  • What is the range?
  • What is the standard deviation?
  • What are the 25th and 75th percentiles?
  • Are there obvious outliers?
  • Is the distribution approximately symmetrical, or is it skewed?

For categorical variables:

  • How many unique categories are there?
  • What are the most common categories?
  • How many observations are in each major category?
  • Are there categories with very few observations?
  • Are there missing or unknown categories?

For dates or time variables:

  • What is the earliest date?
  • What is the latest date?
  • How many observations occur in each relevant time period?
  • Are there gaps in the data?
  • Are some time periods substantially over- or under-represented?

For geographic data:

  • How many unique geographic areas are represented?
  • Which geographic areas have the most observations?
  • Which have the fewest?
  • Are any expected geographic areas missing?

Descriptive statistics prompts

Use the following prompts to guide your analysis, focus on the variables that are most relevant to your final project.

  • What does a typical observation look like in your dataset?
  • What are the most common and least common values or categories?
  • What is the range of values in your most important numerical variables?
  • How different are the observations from one another?
  • Are there unusually large or small values that might affect your analysis?
  • Are there missing values? If so, how many and where?
  • Are some categories much more represented than others?
  • Are there unexpected values that might indicate a data-quality problem?
  • What patterns or distributions do you notice that might be important for your final visualization?
  • What did you learn about your dataset from the descriptive statistics that you did not know before analyzing it?

5. Based on your exploration, identify any problems you found in the data

Consider:

  • Missing values
  • Duplicate records
  • Unexpected values
  • Inconsistent categories
  • Outliers
  • Incorrect data types
  • Gaps in dates
  • Missing geographic areas
  • Other potential data-quality issues

Briefly explain how you will address these issues—or why you have decided to leave them as they are.
